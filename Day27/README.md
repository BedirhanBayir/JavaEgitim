# Day 27 – H2'den MySQL'e Geçiş

Day 26'daki projeyi H2'den MySQL'e taşıdım. Programın söylediği gibi Java kodunda neredeyse hiçbir şey değişmedi: entity, repository, service ve controller'lar aynı. Değişen şey sürücü (driver) ve bağlantı ayarları. Artık veri uygulama kapanınca kaybolmuyor.

```
pom.xml                               ← mysql-connector-j eklendi, h2 sadece test için
resources/application.properties      ← MySQL bağlantısı, ddl-auto=update
resources/data.sql                    ← SİLİNDİ
config/DataLoader.java                ← YENİ: tablo boşsa 5 ürünü ekliyor
src/test/resources/application.properties ← YENİ: testler H2 ile çalışıyor
docker-compose.yml, .env.example      ← YENİ: isteğe bağlı, MySQL'i Docker ile açmak için
```

Programdakine ek olarak:
- **Şifre koda yazılmadı.** Program `spring.datasource.password=sifren_buraya` gösteriyor, ama aynı sayfadaki senior notu şifrelerin commit edilmemesini söylüyor. `application.properties`'te `${DB_PASSWORD}` var; değer ortam değişkeninden geliyor. Değişken verilmezse uygulama `Could not resolve placeholder 'DB_PASSWORD'` hatasıyla açılmıyor. Bunu bilerek bıraktım, böylece şifre unutulursa hemen fark ediliyor.
- **`data.sql` yerine `DataLoader`.** `ddl-auto=update` tabloyu silmediği için `data.sql` her açılışta aynı 5 ürünü tekrar eklerdi: ilk açılışta 5, ikincide 10, üçüncüde 15. `DataLoader` uygulama açılınca çalışıyor ve ürünleri **sadece tablo boşsa** ekliyor. `defer-datasource-initialization` ve `sql.init` ayarlarını da bu yüzden kaldırdım.
- **H2 tamamen silinmedi, scope'u `test` oldu.** `src/test/resources/application.properties` testlerde MySQL ayarlarının yerine geçiyor. `DemoApplicationTests` MySQL kurulu olmayan bir bilgisayarda (veya CI'da) da çalışıyor.
- **URL'e `allowPublicKeyRetrieval=true` ekledim** (3. soruya bakın).
- **`database-platform` (dialect) satırını yazmadım.** Hibernate 6 bağlandığı veritabanını kendisi tanıyor. Yazınca konsolda "MySQLDialect does not need to be specified explicitly" uyarısı çıkıyor.

## Çalıştırma

**1. MySQL'i aç** (ikisinden biri):
- **MySQL kuruluysa:** MySQL Workbench'te `CREATE DATABASE egitimdb;`
- **Docker ile:** `demo` klasöründe `.env.example`'ı `.env` olarak kopyala, içine bir şifre yaz, sonra `docker compose up -d`. `egitimdb` veritabanı otomatik oluşuyor.

**2. Şifreyi uygulamaya ver:** IntelliJ → Run → Edit Configurations → `DemoApplication` → Environment variables → `DB_PASSWORD=şifren`. Kullanıcı `root` değilse `DB_USERNAME=...` da ekle.

**3. Uygulamayı başlat.** Konsolda `HikariPool-1 - Start completed.` ve Hibernate'in `create table products (...)` satırı görünmeli. Sonraki açılışlarda tablo zaten olduğu için `create table` yok.

**4. Kalıcılığı doğrula** (`Day27.postman_collection.json`):
1. `GET /api/products` → 5 ürün
2. `POST /api/products` ile Monitör'ü ekle → 201
3. Uygulamayı durdur ve tekrar başlat
4. `GET /api/products` → Monitör hâlâ orada, ürün sayısı 10 değil 6 (DataLoader tablo dolu olduğu için bir şey eklemedi)
5. MySQL Workbench: `USE egitimdb; SELECT * FROM products;`

## Sorular

**1. H2'den MySQL'e geçerken Java kodunda ne değişti? Neden?**
Entity, repository, service ve controller'larda hiçbir şey değişmedi. Değişenler `pom.xml` (H2 sürücüsü yerine MySQL sürücüsü) ve `application.properties` (bağlantı adresi, kullanıcı, şifre). Tek yeni Java sınıfı `DataLoader`, onu da veritabanı değiştiği için değil, artık veri kalıcı olduğu için ekledim.
Sebebi katmanlar. Kodum hiçbir yerde H2'ye özel bir şey kullanmıyor: `ProductRepository` JPA'yla konuşuyor, JPA (Hibernate) JDBC ile, JDBC de sürücüyle. Hangi veritabanına bağlandığını bilen tek katman sürücü. Hibernate bağlandığı veritabanına göre SQL'i kendisi üretiyor; örneğin `IDENTITY` için H2'de `generated by default as identity`, MySQL'de `auto_increment` yazıyor. `findByCategory` gibi derived query'ler de aynı şekilde iki veritabanında da çalışıyor.

**2. `ddl-auto=update` ile `create-drop` arasındaki fark nedir? Neden `update` kullandık?**
- `create-drop`: açılışta tabloları sıfırdan oluştur, kapanışta sil. Her açılışta boş veritabanı.
- `update`: tablo yoksa oluştur, varsa **dokunma**, sadece entity'ye yeni eklenen alanların sütunlarını ekle. Var olan veri silinmiyor.

H2'de `create-drop` mantıklıydı, zaten bellekteydi. MySQL'e geçmenin amacı verinin kalıcı olması; `create-drop` kullansaydım her yeniden başlatmada bütün ürünler silinirdi. Bu yüzden `update`. `update`'in sınırları da var: sütun silmiyor, adı değişen bir alanı yeni sütun olarak ekliyor (eskisi kalıyor), tip değişikliklerini düzgün yapmıyor. Day 28'de `Product`'a `category_id` eklerken bunu göreceğim. Gerçek projelerde `validate` + Flyway/Liquibase kullanılıyor.

**3. Bağlantı hatası aldıysan ne yaptın? Hata mesajını ve çözümünü yaz.**
MySQL'e bağlanırken en sık görülen hatalar ve çözümleri:

| Hata mesajı | Sebep | Çözüm |
|---|---|---|
| `Communications link failure` / `Connection refused` | MySQL çalışmıyor ya da port yanlış | Windows Hizmetler'de **MySQL80** servisini başlat ya da `docker compose up -d`; portun 3306 olduğunu kontrol et |
| `Access denied for user 'root'@'localhost' (using password: YES)` | Şifre yanlış | `DB_PASSWORD` değerini kontrol et |
| `Access denied ... (using password: NO)` | Şifre hiç gitmedi | `DB_PASSWORD` boş verilmiş |
| `Could not resolve placeholder 'DB_PASSWORD'` | Ortam değişkeni tanımlanmamış | IntelliJ Run Configuration'a ekle |
| `Unknown database 'egitimdb'` | Veritabanı oluşturulmamış | `CREATE DATABASE egitimdb;` (ya da URL'e `createDatabaseIfNotExist=true`) |
| `Public Key Retrieval is not allowed` | MySQL 8'in şifre yöntemi (`caching_sha2_password`), SSL kapalıyken şifreyi şifrelemek için sunucudan açık anahtar istiyor; sürücü bunu varsayılan olarak yasaklıyor | URL'e `allowPublicKeyRetrieval=true` (bu projede ekli) |

Ben `Public Key Retrieval` hatasını önceden önlemek için `allowPublicKeyRetrieval=true`'yu baştan URL'e ekledim. Bu ayar olmadan Docker'daki temiz bir MySQL 8.4'e `useSSL=false` ile ilk bağlantıda bu hata çıkıyor.

**4. JDBC URL yapısı nedir? Her parçanın anlamını açıkla.**
```
jdbc:mysql://localhost:3306/egitimdb?useSSL=false&serverTimezone=UTC&allowPublicKeyRetrieval=true
└─┬┘ └─┬─┘   └───┬───┘ └┬─┘ └──┬───┘ └───────────────────────┬──────────────────────────────┘
 1    2         3      4     5                               6
```
1. `jdbc:` → bu bir JDBC bağlantı adresi.
2. `mysql` → hangi sürücü kullanılacak (alt protokol). PostgreSQL'de `postgresql`, H2'de `h2`.
3. `localhost` → veritabanı sunucusunun adresi. Uzak sunucu için IP veya alan adı yazılıyor.
4. `3306` → port. MySQL'in varsayılanı 3306, PostgreSQL'inki 5432.
5. `egitimdb` → sunucudaki hangi veritabanı.
6. `?` sonrası → sürücü ayarları, `&` ile ayrılıyor:
   - `useSSL=false` → bağlantıyı şifreleme (5. soru)
   - `serverTimezone=UTC` → tarih/saat değerlerinin hangi saat dilimine göre çevrileceği
   - `allowPublicKeyRetrieval=true` → 3. sorudaki hata için

H2'deki `jdbc:h2:mem:testdb`'de ise sunucu ve port yok, `mem:` "bellekte" demek.

**5. `useSSL=false` neden gerekti?**
SSL, uygulama ile MySQL arasındaki trafiği şifreliyor. MySQL 8 sürücüsü varsayılan olarak SSL ile bağlanmaya çalışıyor. Yerelde kurulan bir MySQL'de geçerli bir sertifika olmadığı için eski sürümlerde sertifika uyarıları ve hataları çıkıyordu; `useSSL=false` bunu kapatıyor. Burada sorun değil, çünkü uygulama ile veritabanı aynı bilgisayarda (`localhost`) ve trafik ağa hiç çıkmıyor. Ama veritabanı başka bir sunucudaysa SSL kapatılmamalı, şifre ve veri ağda açık gider. Yeni sürücülerde `useSSL` yerine `sslMode=DISABLED` yazılıyor; `useSSL` hâlâ çalışıyor.

**6. MySQL Workbench veya pgAdmin'de tabloyu gördün mü? Ekran görüntüsünü README'ye ekle.**
MySQL Workbench'te `egitimdb` → Tables altında `products` tablosu görünüyor. Sütunlar: `id` (BIGINT, PK, AUTO_INCREMENT), `category` (VARCHAR(255)), `name` (VARCHAR(255)), `price` (DOUBLE). `SELECT * FROM products;` ile DataLoader'ın eklediği 5 ürün ve Postman'den eklenen ürünler görünüyor.

## Notlar
- Şifreler asla commit edilmiyor: `.env` dosyası `.gitignore`'da, repoda sadece `.env.example` var.
- `ddl-auto=update` geliştirme için rahat ama production'da riskli. Orada `validate` veya `none` + Flyway/Liquibase kullanılıyor.
- Türkçe karakterler için ek ayar gerekmedi: MySQL 8'in varsayılan karakter seti `utf8mb4`.
- PostgreSQL'e geçmek için sadece sürücü (`org.postgresql:postgresql`) ve URL (`jdbc:postgresql://localhost:5432/egitimdb`) değişiyor. Java kodu yine aynı kalıyor.
